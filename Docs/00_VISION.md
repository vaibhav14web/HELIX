# Executive Summary

Helix is a local-first Personal Cognitive Operating System (PCOS).

It is an intelligent orchestration layer that exists between a human and their digital environment.

Helix continuously observes, understands, remembers, suggests, and assists while keeping humans in complete control.

Helix is not a chatbot.

Helix is not a Jarvis clone.

Helix is not an autonomous AI agent.

Helix is a collaborative cognitive system.

Its purpose is to reduce cognitive load and help users work more effectively over long periods of time.

---

# Problem Statement

Modern workflows are fragmented.

Users constantly switch between:

* Browser
* IDE
* Terminal
* AI tools
* Documentation
* Learning platforms

This fragmentation creates:

* Context switching
* Cognitive overload
* Repetitive work
* Information loss
* Reduced productivity

Current AI systems are mostly reactive.

Users repeatedly explain the same things.

Helix aims to solve this.

---

# Storage Philosophy

Laptop SSD:

High speed runtime storage.

Stores:

* Source code
* Models
* Databases
* Embeddings
* Configurations
* Active memory
* Runtime files

External SSD:

Cold storage only.

Stores:

* Backups
* Logs
* Snapshots
* Research datasets
* Archived memories
* Archived projects

Never use the external SSD for runtime execution.

---

# Power Efficiency Philosophy

Power consumption is a first-class feature.

Helix is expected to run daily for several hours.

Rules:

* Idle CPU < 3%
* Idle RAM < 1.5GB
* Idle GPU = 0%
* Continuous GPU usage is forbidden
* Continuous indexing is forbidden
* Continuous scanning is forbidden
* Heavy tasks must be scheduled intelligently

---

# Productivity Philosophy

Every feature must answer:

How does this save time?

If a feature does not save time, remove it.
